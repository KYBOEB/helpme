# Отчёт об использовании нейросетей

По общим правилам хакатона команда указывает: **какие инструменты** использовала,
**на каких этапах** и **для каких задач**.

Отчёт состоит из двух частей, и их важно не путать:

- **Часть 1** — нейросеть внутри самого продукта. Это функциональность решения.
- **Часть 2** — нейросети как инструмент разработки. Это то, чем мы писали код.

---

## Часть 1. Нейросеть внутри продукта

Продукт использует одну внешнюю модель через OpenAI-совместимый эндпоинт
(агрегатор **ProxyAPI**, `https://api.proxyapi.ru/v1`). Провайдер меняется
одной переменной `LLM_BASE_URL` — код при этом не трогается.

| Где | Модель | Что делает | Почему именно так |
|---|---|---|---|
| Классификация обращения (`llm/router.py`) | `LLM_MODEL_FAST` — <<имя из .env>> | По тексту пользователя определяет категорию, выбирает статью из пяти кандидатов, которые дал поиск, и говорит, каких сведений не хватает. Здесь же помечает нецелевые обращения | Задача узкая и частая — берём дешёвую быструю модель. Температура 0.1 |
| Переформулировка шагов (`llm/answerer.py`) | `LLM_MODEL_SMART` — <<имя из .env>> | Переписывает шаги найденной статьи под ситуацию пользователя, формулирует уточняющий вопрос и итог обращения | Здесь важна связность текста, берём модель посильнее |
| Общая рекомендация (`core/assist.py`) | `LLM_MODEL_SMART` | Когда в базе знаний решения нет — даёт общий безопасный совет, честно помеченный как «не из базы знаний» | Второй уровень каскада перед вызовом человека |
| Поиск по базе знаний (`kb/embeddings.py`, `kb/retriever.py`) | `LLM_MODEL_EMBED` — <<имя из .env>> | Переводит текст обращения и карточки базы знаний в векторы; результат объединяется с лексическим поиском BM25 через RRF (k=60) | Лексический поиск не находит перефразировки, синонимы и опечатки. Индекс по карточкам посчитан заранее и лежит в репозитории (`kb/emb_index.npz`), в сети считается только вектор запроса — и тот кэшируется на диск |

**Чего модель делать НЕ может — и это обеспечено кодом, а не просьбой в промпте:**

- не может придумать шаг: если она вернула шагов больше, чем есть в статье,
  берутся шаги статьи как есть (`core/dialog.py`);
- не может сослаться на статью, которой не было в выдаче поиска — такой ответ
  отбрасывается;
- не может изменить состояние обращения: состояние считает сервер, полей `state`
  и `confidence` нет в схеме запроса;
- не может выдать опасный совет в режиме общей рекомендации: отдельный фильтр
  вырезает удаление файлов, форматирование, отключение антивируса, правку реестра,
  сброс к заводским настройкам и ввод паролей.

**Что уходит в модель.** Только текст, очищенный от почты, телефонов, логинов,
IP-адресов и номеров карт (`core/redact.py`). Оригинал обращения остаётся в нашей
базе — он нужен специалисту. Коды ошибок и версии ОС не маскируются: без них
решение невозможно.

**Стоимость** — примерно 0,04 ₽ на обращение, когда решение нашлось в базе
знаний, и около 0,12 ₽, когда пришлось просить у модели общую рекомендацию.
Было 0,24 ₽: раньше на каждое обращение уходило два вызова, теперь на попадании
в базу знаний вызов один. Шаги в карточках написаны подробно, и переписывать их
моделью больше не нужно — код проверяет длину шага и пропускает переформулировку
(`core/dialog.py`, `_steps_are_detailed`).

**Если модель недоступна.** Ответы кэшируются; в режиме `DEMO_MODE=1` система
работает из кэша и не ходит в сеть вообще. При отказе внешнего API обращение
уходит специалисту, а не превращается в ошибку.

## Часть 2. Нейросети как инструмент разработки

Использование нейросетей на хакатоне разрешено, и мы использовали их много —
это было прямой рекомендацией организаторов. Последняя колонка здесь самая
важная: что именно человек проверил или переписал руками после генерации.

## Что мы намеренно НЕ доверили нейросети

- **Содержание базы знаний.** Карточки (122 в финальной версии) вычитаны
  человеком. Сгенерированные
  шаги несколько раз оказывались опасными (удалить папку, отключить защиту) —
  их переписали. Это ровно та причина, по которой в продукте шаги берутся из
  карточек, а не сочиняются моделью на ходу.
- **Решение, что войдёт в MVP.** Список функций и границы решения определяла
  команда.
- **Цифры в README и в отчёте о защите.** Все метрики получены прогонами:
  проверка поиска на перефразировках и опечатках (`tools/check_search.py`),
  19 проверок защиты API, 80 проверок поведения системы, 8 одновременных
  обращений. Ни одна цифра не написана «на глаз». Метрику «полнота поиска
  40 из 40» из отборочного этапа мы сами признали негодной: она считалась
  на вопросах, составленных по тем же карточкам и тем же лексическим
  индексом, то есть измеряла совпадение слов с самими собой. В финальной
  версии README её нет.
- **Ключ доступа к модели.** Лежит только в `.env` на сервере, в репозиторий
  не попадает, в коде не хардкодится.
